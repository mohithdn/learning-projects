CONCEPT 1 / SETUP

Page setup & injected CSS branding

st.set_page_config configures the browser tab, and a block of raw CSS injected through st.markdown(..., unsafe_allow_html=True) gives the app its own look instead of Streamlit's defaults.

It's like decorating a rented apartment: Streamlit hands you the walls and plumbing, and this CSS block is you painting the walls your own color before anyone moves in.

WHY IT MATTERS

Without this, every Streamlit app looks identical — same font, same blue. The .main-title, .subtitle and .metric-card classes are what make this dashboard feel like a distinct product.

TRY IT

.main-title { color: ...; font-size: ...px; }
🔎 Data Detective Agent
Upload your transaction CSV and investigate your data.

CODE, FROM app_p6.py

app_p6.py
st.markdown("""
<style>
    .main-title { font-size: 38px; color: #1f4e79; }
</style>
""", unsafe_allow_html=True)

st.markdown('<div class="main-title">🔎 Data Detective Agent</div>', unsafe_allow_html=True)
PITFALL unsafe_allow_html=True renders whatever HTML you pass it, no questions asked. It's fine for your own hardcoded strings — never pass user-uploaded text through it, or you'd open the door to injected scripts.
CONCEPT 2 / INGESTION

The upload gate & st.stop()

The whole dashboard below only makes sense once there's a file to analyze — so the script checks for one first, and calls st.stop() to halt everything else if there isn't.

It's a locked turnstile at a train station: nobody gets to the platform (the dashboard code) until they've tapped a card (uploaded a file).

TRY IT

uploaded_file
No file
File uploaded

CODE, FROM app_p6.py

app_p6.py
if uploaded_file is None:
    st.info("📂 Please upload a CSV file from the sidebar to begin.")
    # ...show the "what this app can do" preview...
    st.stop()  # nothing below this line runs

# everything from here on assumes a file exists
df = pd.read_csv(uploaded_file)
PRO TIP st.stop() is different from return — it halts the entire script execution immediately, which is exactly what you want at top level in a Streamlit file where there's no function to return from.
CONCEPT 3 / INGESTION

Reading the CSV safely

A try/except around pd.read_csv catches malformed files and shows a friendly error instead of letting the whole app crash with a stack trace.

It's a bouncer checking IDs at the door: a real, well-formed file gets waved through; anything broken gets turned away with an explanation, not a scene.

TRY IT

try: pd.read_csv(uploaded_file)

CODE, FROM app_p6.py

app_p6.py
try:
    df = pd.read_csv(uploaded_file)
except Exception as e:
    st.error(f"❌ Could not read the CSV file: {e}")
    st.stop()
PRO TIP Catching the broad Exception here is deliberate — a CSV can fail to parse in many different ways (bad encoding, wrong delimiter, truncated file), and the user just needs to know "it didn't work," not the exact exception class.

CONCEPT 6 / CLEANING & STATS

Missing-value cleaning strategies

Three different fixes for the same problem — drop the row, fill with the column's average, or fill with zero — each with a real trade-off in how much data you keep versus how much you distort it.

TRY IT

missing revenue values in a sample table
 

CODE, FROM app_p6.py

app_p6.py
if cleaning_option == "Remove rows with missing values":
    df = df.dropna()

elif cleaning_option == "Fill numeric missing values with mean":
    for column in df.select_dtypes(include="number").columns:
        df[column] = df[column].fillna(df[column].mean())

elif cleaning_option == "Fill missing values with 0":
    df = df.fillna(0)
PITFALL fillna(0) is tempting because it's simple, but for a column like revenue it silently invents "free" transactions — that can quietly wreck an average. fillna(mean) is usually the gentler choice for numeric data.
CONCEPT 7 / CLEANING & STATS

Summary statistics

describe() runs count, mean, std, min, quartiles and max on every numeric column in one call — a full statistical snapshot with zero manual math.

TRY IT

numeric_df.describe()

CODE, FROM app_p6.py

app_p6.py
numeric_df = df.select_dtypes(include="number")

if numeric_df.empty:
    st.warning("No numeric columns found in this dataset.")
else:
    st.dataframe(numeric_df.describe(), use_container_width=True)
PRO TIP The empty-check matters: a CSV of pure text columns (names, cities, notes) has no numeric columns at all, and calling .describe() on an empty frame would just render a confusing blank table instead of a clear message.
CONCEPT 8 / VISUALIZATION & EXPORT

Finding the revenue column automatically

Instead of asking the user to pick which column is "revenue," the app scans every column name for the substring "revenue", case-insensitively, and uses the first match.

It's like scanning a bookshelf by spine title instead of asking someone to hand you the exact book — as long as the word is somewhere in the name, it gets found.

TRY IT

[col for col in df.columns if "revenue" in col.lower()]
 

CODE, FROM app_p6.py

app_p6.py
revenue_columns = [
    col for col in df.columns
    if "revenue" in col.lower()
]

if revenue_columns:
    revenue_column = revenue_columns[0]  # just takes the first match
PITFALL If a CSV has both "Revenue_2023" and "Revenue_2024", this silently picks whichever column comes first — worth double-checking the metric labeled "Revenue Analysis" is actually the column you meant.
CONCEPT 9 / VISUALIZATION & EXPORT

Revenue distribution histogram

A histogram groups numeric values into buckets ("bins") and draws a bar for how many values fall in each — turning a long column of numbers into one shape you can read at a glance.

TRY IT

CODE, FROM app_p6.py

app_p6.py
fig = px.histogram(
    df, x=revenue_column, nbins=20,
    title="Revenue Distribution",
    labels={revenue_column: "Revenue"}
)
fig.update_layout(bargap=0.1)
st.plotly_chart(fig, use_container_width=True)
PRO TIP Too few bins hides structure (everything looks like one lump); too many bins turns the histogram into noisy spikes. nbins is a dial worth tuning per dataset, not a value to hardcode and forget.

Key takeaways

  • Guard the entry point. The upload check and st.stop() mean every line below can safely assume a valid file exists — no defensive checks scattered everywhere else.
  • Fail loud in code, fail soft on screen. The try/except around read_csv turns a crash into a readable message, which is the difference between a tool people trust and one they abandon.
  • Detect, don't demand. Auto-finding the revenue column by name, and auto-listing categorical columns by dtype, means the user barely has to configure anything.
  • Every transform is a trade-off. Dropping rows, filling with the mean, and filling with zero all "solve" missing data differently — the right one depends on what the numbers mean.
What this unlocks next: upload → validate → clean → analyze → visualize → export is the same shape behind almost any data tool you'll build — a survey analyzer, a sales dashboard, a log inspector. Swap the charts and cleaning rules, and the skeleton still holds.
